# PomidorQA — автотесты (Playwright + TypeScript)

Набор автотестов для [PomidorQA](https://aiqa.su/pomidorqa) — сервиса коротких
25-минутных встреч для QA/IT-специалистов: регистрация, профиль с навыками,
свободные слоты, каталог, бронирование встреч и их отмена.

Тестируется живой сайт: e2e-сценарии гоняют реальный браузер против `aiqa.su`,
данные готовятся через служебное API и гарантированно удаляются после каждого теста.

> Проект вырос из марафона «Автоматизация на Playwright + TypeScript» (aiqa.su/pomidorqa):
> эталонные тесты, `CODEX.md` и `REVIEW.md` — материалы курса; доработки, рефакторинг
> структуры и тесты авторизации — мои.

## Что покрыто

- **E2E (браузер, живой стенд):**
  - сквозное бронирование + гонка двух гостей за один слот;
  - отмена бронирования: карточка уходит в «Прошедшие и отменённые», видят оба участника;
  - вход и выход: logout разлогинивает, повторный вход через форму возвращает аккаунт;
  - регистрация: успешная форма сразу авторизует, занятый email даёт ошибку;
  - негативный вход: одинаковая ошибка для неверного пароля и несуществующего email;
  - профиль: имя, telegram, «о себе», часовой пояс, навыки — сохранение подтверждается
    перезагрузкой страницы (данные с сервера, а не из формы).
- **API:** бизнес-правила бронирования на локальном мок-сервере — занятость слота,
  собственный слот, прошедшая дата, гонка запросов, дубликат email.
- **Unit:** чистые функции — пересечение слотов, форматирование времени по поясам,
  валидация пароля.

## Подход

- **Пирамида тестов:** unit → api → e2e, каждый сценарий на минимально достаточном уровне.
- **Page Object Model:** локаторы и действия экрана в `tests/pages/` (`LoginPage`,
  `RegisterPage`, `ProfilePage`, `BookingPage`), в spec — только сценарий и проверки.
- **Подготовка через API:** пользователи создаются `POST /api/pomidorqa/test/accounts`
  (arrange за миллисекунды вместо UI-формы), страница того же контекста уже авторизована.
- **Гарантированная очистка:** `afterEach` для fixture-контекстов, `try/finally` для
  созданных внутри теста; DELETE каскадно снимает навыки, слоты и бронирования.
- **Анти-флак правила:** без `waitForTimeout`/`force`/`pause`/`.only` (закреплено ESLint),
  web-first assertions, ожидание ответа сервера до действия, `expect().toPass()` для
  медленных участков. Новые тесты прогоняются `--repeat-each=10`.
- **Правила кода:** [CODEX.md](./CODEX.md), чеклист ревью — [REVIEW.md](./REVIEW.md).
- **ИИ-обвязка:** правила для агентов (`AGENTS.md`) и скилы (`.agents/`, `.cursor/`) —
  агент пишет тесты по кодексу, проверяет локаторы по живому DOM и гоняет гейты.

## Запуск

```bash
npm install
npx playwright install chromium

npm test            # все уровни: unit + api + e2e
npm run test:unit   # без сети и браузера
npm run test:api    # HTTP к локальному мок-серверу
npm run test:e2e    # браузер на живом aiqa.su
npm run lint        # ESLint (playwright-правила)
npm run report      # HTML-отчёт последнего прогона
```

E2E бьют в продакшен по умолчанию; адрес стенда переопределяется переменной
`POMIDORQA_BASE_URL`.

## Структура

```
src/pyramid/         чистые функции и локальный мок-сервер для api-тестов
tests/unit/          unit-тесты
tests/api/           api-тесты (мок-сервер)
tests/e2e/           браузерные сценарии
tests/helpers/       данные и вход: makeUser, registerUser(ViaApi), deleteUserViaApi
tests/pages/         Page Object'ы экранов
.github/workflows/   CI: lint + все тесты на каждый PR и push в main
```

## CI

GitHub Actions: ESLint и полный прогон (unit, api, e2e против живого стенда) на каждый
pull request и push в `main`; HTML-отчёт сохраняется артефактом. Один worker и один retry
в CI — общий стенд, меньше конкуренции за слоты.
